# 학습 페이지 규격 — 유일한 기준

_박 목사님이 2026-08-27 에 정하셨다. 이 문서가 유일한 기준이다._

**같은 값을 두 곳에 적지 마라.** 프롬프트나 리뷰 문서에 이 규격을 베껴 넣지
말고 이 파일을 가리켜라. 베껴 두면 반드시 한쪽만 고쳐진다.

기준은 셋이고, 각각 이미 저장소 안에 살아 있는 과목에서 왔다.

| 무엇 | 어디서 왔나 | 어디를 보면 되나 |
|---|---|---|
| 내용·형식 | **부동산공법** | `public/public-law-p*.dat` (gzip+base64, 아래 여는 법) |
| 카테고리 분류 | **부동산세법** | `src/data/taxLaw.js` |
| 계산문제 | **부동산학개론** | `src/data/realEstateTheoryCalculations.js` |

공법 원문을 열어 보려면:

```bash
cat public/public-law-p*.dat | tr -d '\n' | base64 -d | gunzip > /tmp/publiclaw.html
```

## 1. 내용·형식 — 공법 규격

한 단원(절·POINT·장)은 **여덟 조각**으로 이루어진다. 순서도 이대로다.

### ① 📌 핵심 한줄 (`tldr`)

그 단원에서 시험에 나오는 판단 기준을 한 문장으로. 주체·요건·수치를 굵게.

> 📌 광역계획권 지정은 **국토교통부장관(둘 이상 시·도) / 도지사(같은 도 안)**.
> … **3년** 지나도록 승인신청 없으면 상급자 수립.

### ② 📘 이 단원을 조금 더 자세히 이해하기 (`section-deep`)

**네 칸 고정이다. 칸을 늘리거나 줄이지 마라.**

1. **① 제도의 목적·의미** — 왜 이 제도가 있나
2. **② 법률상 구조** — 무엇이 먼저 오고 무엇이 뒤따르나
3. **③ 문제를 푸는 판단순서** — 문제를 보면 무엇부터 갈라 보나
4. **④ 자주 틀리는 포인트** — 수험생이 실제로 헷갈리는 지점

그 아래 **🧠 연결 암기** 한 줄로 전체 흐름을 한 줄에 꿴다.

### ③ 비교표 (`card`)

`<table>` 로 구분·주체·절차를 나란히 놓는다. 첫 열은 `class="k"`(구분 키).
표로 다 담기지 않는 보충은 표 아래 `<ul>` 로.

**표가 없으면 그 단원은 미완성이다.** 공인중개사 시험은 "누가 / 언제까지 /
가능한가 불가능한가" 를 가르는 문제가 대부분이고, 그것은 줄글로는 안 외워진다.

### ④ 🧭 절차 인포그래픽 (`inline-proc`)

절차가 있는 단원에만 넣는다. 세 부분이다.

- **흐름** — 단계 상자를 `→` 로 잇는다. 각 상자에 한 줄 설명(`<small>`)
- **표** — `단계 / 세부 내용 / 시험 포인트` 세 열
- **정리 포인트** — 이 절차에서 시험이 노리는 한 가지

### ⑤ ⚠️ 시험 출제 포인트 (`box point`)

실제로 출제된 갈림길. "A는 의무, B는 임의" 처럼 **대비되는 짝**으로 적는다.

### ⑥ 🧠 암기 (`box memo`)

외울 말. 짧아야 한다. 예: `"3년 안 내면 위에서 짠다"`

### ⑦ 확인문제 (`check` / `q` / `a`)

단원마다 최소 하나. 답과 함께 **왜 그런지**를 한 줄 붙인다.

### ⑧ 색·강조 규칙

의미가 정해져 있다. 예쁘라고 쓰는 것이 아니다.

| 표시 | 뜻 | 예 |
|---|---|---|
| `b must` | 필요적·의무 | **개최 의무** |
| `b who` | 주체(누가) | **국토교통부장관** |
| `b num` | 수치·기한 | **3년**, **30일** |
| `b no` | 불가·제외 | **불요**, **할 수 없다** |
| `k` | 표의 구분 키 열 | 첫 열 |

## 2. 카테고리 분류 — 세법 규격

**4단계다.** 세법이 이미 이렇게 되어 있고(`src/data/taxLaw.js`), 목차 정리가
가장 잘 된 과목이라 이것을 전 과목에 적용한다.

```
카테고리(PART)  →  대분류(POINT)  →  중분류(group)  →  소분류(topic)
PART 1 조세총론 →  POINT 01        →  조세의 기본개념 →  조세의 의의
                   조세의 개념과 분류    (6개)            조세의 특징
                                                        조세법률주의 …
```

데이터 모양:

```js
{ id, number, title, color, points: [
  { id, number, title, groups: [
    { title: '중분류 이름', topics: ['소분류', '소분류', …] }
  ]}
]}
```

**소분류는 목차이지 본문이 아니다.** 소분류 하나하나에 §1 의 여덟 조각을
다 넣으라는 뜻이 아니다. 여덟 조각은 **대분류(POINT) 단위**로 채운다.

## 3. 계산문제 — 학개론 규격

계산이 나오는 단원은 카드로 만든다. **열한 필드가 정해져 있다.**

| 필드 | 뜻 |
|---|---|
| `title` | 무엇을 구하는 계산인가 |
| `source` | 근거 (교안 쪽수·법조문) |
| `formula` | 공식 |
| `when` | 언제 이 공식을 쓰나 |
| `find` | 무엇을 먼저 찾아야 하나 |
| `steps[]` | 풀이 순서 |
| `calculator` | **계산기 입력 예시** — 시험장에서 그대로 두드릴 수 있게 |
| `example` | 숫자를 넣은 예 |
| `result` | 그 예의 답 |
| `trap` | 이 계산에서 자주 틀리는 것 |
| `tip` | (선택) 요령 |

`calculator` 를 빠뜨리지 마라. 이 규격이 다른 계산 정리와 다른 점이 바로
그것이다 — 공식을 아는 것과 계산기로 두드리는 것은 다른 일이다.

## 4. 지어내지 않는다 — 이 규칙이 가장 무겁다

시험 콘텐츠다. 틀린 조문이나 낡은 세율을 그럴듯하게 적으면 **학습자가 틀린
것을 외운다.** 되돌릴 수 없는 종류의 잘못이다.

- 조문 번호·기한·세율·면적·금액은 **국가법령정보센터(law.go.kr) 현행법령에
  근거가 있을 때만** 적는다.
- 근거를 확인하지 못하면 **그 항목을 뺀다.** 비슷한 것으로 채우지 마라.
  (앞 파이프라인에서 뜻이 없는 3항목을 지어내는 대신 300→297 로 줄였다.)
- 기존 본문을 **규격에 맞게 옮기는 것이 이번 일의 본체다.** 없던 내용을 새로
  지어내는 일이 아니다. 옮기다가 원문에 없는 것을 채워 넣지 마라.
- 확신이 없으면 그 자리에 `<!-- 확인 필요: … -->` 를 남기고 0-lead 에게
  보고하라. 조용히 지어내는 것보다 낫다.

**규칙은 표결이 아니라 선례로 정한다.** 모델 여럿이 달리 말해도 이미 배포된
데이터가 우선이다. 확신이 없으면 배포본을 `grep` 해서 확인하라.

## 5. 무엇을 만드는 물건인가 — 시험 대비

_박 목사님 지시 2026-08-27._

이것은 **2026 제37회 공인중개사 시험을 준비하는 사람이 이것만 보고 시험장에
들어갈 수 있는** 물건이다. 개념을 소개하는 글이 아니다. **최대한 자세하게,
시험이 묻는 방식에 맞춰** 채워라.

### 분량을 아끼지 마라

한 단원을 다 읽었을 때 **그 단원에서 나올 수 있는 문제를 다 풀 수 있어야
한다.** "핵심만 간추렸습니다" 는 이 물건의 목표가 아니다.

다만 **근거 없는 분량은 분량이 아니라 오답이다.** §4 를 먼저 지켜라.
지어낸 한 줄이 정확한 열 줄보다 해롭다.

### 시험이 실제로 묻는 것을 채워라

- **갈림길을 표로 세워라.** 시험은 "A는 되고 B는 안 된다" 를 묻는다.
  줄글로 열 줄 쓰는 것보다 표 한 개가 낫다. 주체·요건·기한·효과를 열로.
- **숫자를 빠뜨리지 마라.** 기한(30일·60일·3년), 비율, 면적, 금액, 세율,
  정족수. 시험은 숫자를 바꿔서 낸다. `b num` 으로 눈에 띄게.
- **누가 하는지를 늘 밝혀라.** 신청·결정·승인·통지의 주체가 다르면 그것이
  문제다. `b who` 로.
- **예외와 단서를 적어라.** "원칙은 A, 다만 B인 경우 C" — 시험은 단서에서
  낸다. 원칙만 적으면 반쪽이다.
- **비슷한 것끼리 나란히 놓아라.** 광역도시계획 vs 도시·군기본계획,
  취득세 vs 등록면허세, 대항력 vs 우선변제권.
- **함정 선지를 적어라.** 실제로 틀리는 지점을 "이렇게 나오면 틀린 것" 형태로.
- **판례가 결론을 가르면 판례를 적어라.** 조문만으로 안 풀리는 것이 있다.

### 확인문제는 시험 문제처럼

단원마다 **최소 3개.** 하나로는 그 단원을 점검할 수 없다.

- 실제 기출의 묻는 방식을 따라라 (O/X, 옳은 것은, 옳지 않은 것은)
- 답만 적지 말고 **왜 그런지**를 한 줄 붙여라
- 틀린 선지는 **어디를 어떻게 바꾸면 맞는 말이 되는지** 적어라

### 계산 단원은 계산기까지

§3 의 열한 필드를 다 채워라. 특히 `calculator` — **시험장에서 그대로
두드릴 수 있는 입력 순서**다. 공식을 아는 것과 계산기를 두드리는 것은
다른 일이고, 시험장에서 무너지는 곳은 후자다.

### 한 단원을 끝냈는지 스스로 묻는 법

1. 이 단원에서 나온 최근 기출을 이 글만 보고 풀 수 있나?
2. 주체·기한·요건·효과·예외가 다 적혀 있나?
3. 헷갈리는 짝이 표로 나란히 있나?
4. 숫자가 다 있고 근거가 있나?
5. 확인문제가 그 단원의 핵심을 묻나?

하나라도 아니면 아직 덜 채운 것이다.
