# 역할과 폴백 — realtor-exam 규격 통일 파이프라인

## 3차 구조

한 덩어리는 **단원 하나**다. 다섯 산출물로 끝난다.

| 차 | 누가 | 산출물 | 하는 일 |
|---|---|---|---|
| — | **0-lead** | `01-plan.md` | 명세를 쓴다. 직접 쓴다 |
| 1차 **실행** | `codex` (GPT) | `02-impl.md` | 명세대로 구현하고 요약을 남긴다 |
| 2차 **검증** | `agy` (Gemini) | `03-review.md` | 빌드를 **직접 돌려** 보고 PASS/FAIL. **코드 수정 금지** |
| 3차 **리뷰** | `claude` | `03b-review.md` | 규격 준수·설계·놓친 것. **코드 수정 금지** |
| — | **0-lead** | `04-decision.md` | 판단. 직접 쓴다 |

**세 차가 서로 다른 계열이어야 한다.** 같은 계열이 구현하고 검증하면 자기가
못 본 것을 또 못 본다. 교차검증은 계열이 달라야 뜻이 있다.

## 되돌아가기

2차나 3차가 FAIL 이면 1차로 되돌려 재실행하고 다시 검증한다. **최대 3회.**
세 번째도 FAIL 이면 멈추고 `04-decision.md` 에 무엇이 왜 막혔는지 적고
박 목사님께 보고한다. 무한 반복은 패널을 통째로 잡아먹는다.

## 폴백

- 한 모델이 쿼터로 쉬면 dispatcher 가 **다른 계열**로 넘긴다. 같은 계열은
  같은 오류를 공유하므로 넘겨도 소용이 없다.
- 2회 실패하면 모델 승계, 6회 실패하면 `.dead` 를 남기고 큐에서 뺀다.
  `.dead` 가 생기면 0-lead 가 봐야 한다.
- 한 단원의 실패가 루프 전체를 죽이지 않게 격리한다.

## 공급원 한도 — 계정 단위다

`agy 4 / codex 3 / claude 3`. **파이프라인 단위가 아니라 계정 단위다.**

- `agy` 는 Gemini 계열 **전부가 한 쿼터**를 나눠 쓴다. 많이 물려도 안 빨라진다.
- `codex` 따로, `claude` 따로.
- 다른 파이프라인을 같이 돌리면 합쳐서 넘겨 양쪽 다 쿨다운에 걸린다.

## 절대 규칙

전부 실제로 사고가 나서 생긴 것이다.

- **PR 은 반드시 Draft 로 만든다** (`gh pr create --draft`). Ready 전환과
  병합은 박 목사님이 한다.
- **`git add -A` 를 쓰지 마라.** 경로를 하나씩 지정한다.
- **`main` 에서 직접 작업하지 마라.** 작업 브랜치를 판다.
- **검증기를 통과시키려고 검증기를 고치지 마라.**
- **없는 데이터를 지어내지 마라.** 원본에 없으면 그 항목을 뺀다. → `SPEC.md` §4
- **`git reset --hard` 를 `.pipeline/` 이 살아 있는 채로 쓰지 마라.**
- **`cmux-work-os` 를 부르지 마라.** 샌드박스 밖이라 EPERM 으로 막힌다.
- **완료는 산출 파일의 존재로 판정한다.** 로그나 화면으로 판정하지 마라.
- **과제 폴더를 덮어쓰지 마라.** 새 과제는 `taskN+1` 로 만든다.

내용·형식·분류·계산 규격은 **`.pipeline/SPEC.md` 하나뿐이다.** 여기에도
